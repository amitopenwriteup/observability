📌 DQL Query for CPU SLO

timeseries avg(dt.host.cpu.usage), by: {dt.entity.host} | filter avg(dt.host.cpu.usage) < 80 | fieldsAdd slo_met = if(avg(dt.host.cpu.usage) < 80, 1, 0)

📌 Log Error Rate Formula

Error Rate = (ERROR + CRITICAL logs) / Total Logs × 100 Target: Error Rate < 1.0% Acceptable Errors: 99% of time periods must meet target
Step 1.1: Select "Metric expression" for SLO type
Step 1.2: Create DQL query for error rate
fetch logs | filter matchesPhrase(content, "ERROR") or matchesPhrase(content, "CRITICAL") | summarize error_count = count(), by: {bin(timestamp, 5m)} | lookup [ fetch logs | summarize total_count = count(), by: {bin(timestamp, 5m)} ], sourceField:timestamp, lookupField:timestamp | fieldsAdd error_rate = (error_count / total_count) * 100 | filter error_rate < 1.0
Step 1.3: Set success criteria: error_rate < 1%
Step 1.4: Configure timeframe: Rolling 7 days
Step 1.5: Set target: 99% of measurements pass

Advanced DQL Techniques

🚀 Power User DQL Patterns

1. Multi-SLO Aggregation
// Calculate overall SLO compliance across multiple services fetch dt.entity.service | fields service = entity.name, slo_cpu, slo_memory, slo_uptime | fieldsAdd overall_compliance = (slo_cpu + slo_memory + slo_uptime) / 3 | filter overall_compliance < 99.9 | sort overall_compliance asc
2. Predictive Error Budget Exhaustion
// Predict when error budget will be exhausted based on current burn rate timeseries budget_remaining = avg(error_budget_percentage) | fieldsAdd burn_rate = (budget_remaining[now-1h] - budget_remaining[now]) / 1h | fieldsAdd hours_remaining = budget_remaining / burn_rate | fieldsAdd exhaustion_time = now() + hours_remaining * 3600000
3. Comparative Analysis
// Compare current week vs previous week performance timeseries current_week = avg(builtin:host.cpu.usage), filter: { timeframe(now-7d, now) } | lookup [ timeseries previous_week = avg(builtin:host.cpu.usage), filter: { timeframe(now-14d, now-7d) } ], sourceField: timestamp, lookupField: timestamp | fieldsAdd improvement_pct = ((previous_week - current_week) / previous_week) * 100
4. Anomaly Detection with Baseline
// Detect when metrics deviate from 30-day baseline timeseries current = avg(builtin:host.cpu.usage) | lookup [ timeseries baseline = avg(builtin:host.cpu.usage), filter: { timeframe(now-30d, now-7d) } ] | fieldsAdd deviation = abs(current - baseline) | fieldsAdd is_anomaly = if(deviation > baseline * 0.3, true, false) | filter is_anomaly == true

Dashboard Performance Optimization

⚠️ Common Performance Pitfalls

  • Too many tiles (> 20) on a single dashboard
  • Queries spanning more than 30 days without sampling
  • High-cardinality grouping (thousands of unique values)
  • Auto-refresh interval < 30 seconds for complex queries

✅ Optimization Techniques

Issue Solution
Slow queries on large timeframes Use sampling: | sample 1000
Too many metrics per tile Split into multiple focused tiles
High-cardinality data Use | limit 10 or filter to top/bottom
Dashboard load time > 5s Reduce auto-refresh frequency, use management zones
Tip 3.1: Use management zones to scope dashboards

Tip 3.3: Set appropriate time ranges (default to 24h for operational dashboards)

Troubleshooting Common Issues

🔧 Common Issues and Solutions

Issue 1: SLO Shows "No Data"
Possible Causes:
  • Incorrect metric selector
  • No entities match the filter
  • Management zone doesn't include hosts
  • Time range too short
Solution:
// Verify metric exists fetch dt.entity.host | fields entity.name | limit 1 // Check if data is flowing fetch builtin:host.cpu.usage | summarize count()
Issue 2: Error Budget Calculation Incorrect
Debugging Steps:
  • Verify SLO evaluation window matches expectations
  • Check if success criteria are inverted
  • Confirm percentile calculations are correct
  • Review historical data for gaps
Issue 3: Dashboard Loading Slowly
Optimization Checklist:
  • ✓ Reduce time range to 24h or less
  • ✓ Limit tiles to < 15 per dashboard
  • ✓ Use sampling for large datasets
  • ✓ Apply entity filters early in query
  • ✓ Increase auto-refresh interval
Issue 4: Alerts Not Firing
Verification Steps:
1. Check alerting profile is applied 2. Verify notification channels are configured 3. Confirm alert rule conditions are met 4. Check if alert is in maintenance window 5. Review problem detection sensitivity settings
