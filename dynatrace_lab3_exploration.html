LAB 3

Exploring Dynatrace After OneAgent Installation

Understanding Host, Process & Service Discovery

🎯 Lab Objectives

Duration: 30-40 minutes

Difficulty: Beginner to Intermediate

What You'll Learn:

  • Navigate and understand the Dynatrace host view
  • Explore process-level monitoring and metrics
  • Discover automatically detected services
  • Understand Smartscape topology visualization
  • Analyze distributed traces with PurePath
  • Create your first custom dashboard

Prerequisites

  • Completed LAB 1: Dynatrace SaaS account setup
  • Completed LAB 2: OneAgent installed on Linux host
  • Host has been monitored for at least 10-15 minutes
  • Some application traffic running (web server, database, etc.)
⏱️ Wait Time: If you just installed OneAgent, wait 10-15 minutes for full discovery. You'll see the host immediately, but services and full topology need some time and traffic to be detected.

Part 1: Host-Level Monitoring

1 Navigate to Hosts View
  • In the left navigation menu, click "Infrastructure"
  • Click "Hosts"
  • You should see your monitored host listed
  • Note the health status icon (green = healthy)
📸 Screenshot: Hosts list view showing your Linux host
2 Explore Host Details
  • Click on your host name to open the host detail page
  • Observe the top section showing:
    • Host name and IP address
    • Operating system and version
    • CPU cores and total memory
    • OneAgent version
    • Monitoring status and health

📊 Host Overview Sections

Properties: Static information about the host

Health: Current health status and alerts

Processes: Number of running processes detected

Monitoring: OneAgent configuration and status

3 Analyze Host Metrics
  • Scroll down to view the metrics charts:
    • CPU usage: Overall and per-core utilization
    • Memory: Used vs available, swap usage
    • Disk: I/O operations, throughput, latency
    • Network: Traffic in/out, errors, retransmissions
  • Click on any metric chart to see detailed view
  • Use the time selector (top right) to change time range
  • Try different time ranges: Last 2 hours, Last 6 hours, Last day
💡 Pro Tip: Click and drag on any chart to zoom into a specific time period. Right-click to reset the zoom.

✏️ Exercise 1: Host Analysis

Answer these questions by exploring your host:

  • What is the average CPU usage over the last hour?
  • How much memory is currently being used?
  • What is the network traffic pattern?
  • Are there any disk I/O bottlenecks?

Part 2: Process-Level Monitoring

4 View All Processes
  • From the host detail page, scroll down to "Processes" section
  • Or navigate to: Infrastructure → "Processes and Containers"
  • You'll see all detected processes grouped by technology
  • Notice different process types:
    • Application processes (Java, .NET, Node.js, etc.)
    • Web servers (Apache, NGINX)
    • Databases (MySQL, PostgreSQL, MongoDB)
    • System processes

🔍 Process Classification

Dynatrace automatically classifies processes:

  • Monitored: Deep instrumentation and code-level visibility
  • Detected: Infrastructure monitoring only
  • System: OS-level processes (not instrumented)
5 Explore a Process
  • Click on any monitored process (look for technology icons)
  • Observe the process detail page showing:
    • Process name and technology type
    • Running on which host
    • Process group classification
    • Resource consumption (CPU, memory)
    • Services detected within this process
  • Review the metrics:
    • CPU: Process-specific CPU usage
    • Memory: Heap, non-heap (for JVM/.NET)
    • Threads: Thread count over time
    • GC: Garbage collection stats (JVM)
6 Understanding Process Groups
  • Click on "Process groups" in the left navigation
  • Process groups combine similar processes:
    • Same technology and application
    • Running across multiple hosts
    • Provides aggregated view
  • Useful for:
    • Monitoring clustered applications
    • Comparing instances
    • Setting alerts at group level
✅ Key Insight: Process Groups allow you to monitor multiple instances of the same application as a single logical entity, even when spread across different hosts.

✏️ Exercise 2: Process Analysis

Explore your processes and identify:

  • Which process is consuming the most CPU?
  • How many Java/.NET processes are running?
  • What is the memory footprint of your main application?
  • Are there any web server processes detected?

Part 3: Service Discovery & Analysis

7 Navigate to Services
  • In the left menu, click "Services"
  • You should see automatically discovered services
  • If no services appear yet:
    • Wait a few more minutes
    • Ensure your application is receiving traffic
    • Generate some requests to your application
⚠️ Note: Services are discovered based on actual traffic. If your application hasn't received any requests, no services will be detected yet. Make sure to send some test requests to your application.
8 Explore Service Details
  • Click on any discovered service
  • Review the service overview:
    • Service name: Auto-generated based on technology
    • Technology: Framework and language
    • Response time: Average, median, percentiles (P50, P90, P95)
    • Throughput: Requests per minute
    • Failure rate: Percentage of failed requests
  • Scroll down to view:
    • Top requests: Most frequent endpoints
    • Database calls: SQL queries and databases accessed
    • Dependencies: Services this service calls
    • Instances: Where the service is running
9 Analyze Service Flow
  • On the service detail page, click "Service flow" button
  • This shows visual representation of:
    • Incoming traffic sources
    • This service in the middle
    • Outgoing calls to databases, external services
  • Hover over connections to see:
    • Request count
    • Response time contribution
    • Error rates

📊 Service Flow Benefits

Service flow helps you understand:

  • Where requests are coming from
  • Which dependencies are causing delays
  • Impact of database or external service calls
  • Overall request path and bottlenecks

✏️ Exercise 3: Service Analysis

For your primary service, determine:

  • What is the average response time?
  • What is the P95 response time?
  • Which endpoint is slowest?
  • What databases does it connect to?
  • Are there any external service dependencies?

Part 4: Smartscape Topology

10 Open Smartscape
  • Click on "Smartscape topology" in the left menu
  • Or from any entity page, click the "Smartscape" button
  • You'll see an interactive topology map of your environment
📸 Screenshot: Smartscape topology showing hosts, processes, and services
11 Navigate Smartscape
  • Use the vertical stack view (default):
    • Top: Data centers, hosts
    • Middle: Processes, process groups
    • Bottom: Services
  • Click on any entity to:
    • Highlight its dependencies
    • See incoming and outgoing connections
    • View quick metrics
  • Try different filters:
    • Filter by technology
    • Filter by tag
    • Show/hide different entity types
  • Use the time travel feature:
    • Select different time in the past
    • See how topology changed over time
💡 Pro Tip: Double-click on any entity in Smartscape to drill down and see only its direct dependencies. This helps focus on specific parts of complex topologies.
12 Understand Dependencies
  • Click on your main service in Smartscape
  • Observe the highlighted connections showing:
    • Calls from: What's calling this service (upstream)
    • Calls to: What this service calls (downstream)
  • Follow the complete request path:
    • From user/browser
    • Through web server
    • To application service
    • To database
✅ Key Insight: Smartscape automatically builds and maintains this topology in real-time. No configuration required—it learns from actual traffic patterns.

✏️ Exercise 4: Topology Exploration

Using Smartscape, map out:

  • Draw your complete technology stack on paper
  • Identify all services and their connections
  • Note which service has the most dependencies
  • Identify any external service calls
