Dynatrace Pattern Language

(DPL)

A powerful pattern matching language for log parsing and data extraction

What is DPL?

DPL is a pattern language that uses matchers - mini-patterns that match specific data types.

🎯Pattern Matching

Describe patterns using intuitive matchers like INTEGER, IPADDR, TIMESTAMP

📊Data Extraction

Parse and extract structured data from unstructured logs

🔍Flexible Parsing

Handle various data formats with schema-on-read approach

⚡High Performance

Efficient left-to-right interpretation for fast processing

DPL Use Cases

📝 Log Parsing - Extract structured fields from application logs
🔐 Security Analysis - Parse security events and identify patterns
📈 Performance Monitoring - Extract metrics from performance logs
🐛 Troubleshooting - Identify patterns in error logs and traces
💼 Business Analytics - Extract business events from application logs
🌐 Network Analysis - Parse network logs and traffic data

Basic Pattern Syntax

Simple one-liner pattern:

INT ' ' IPADDR:ip EOL

Same pattern with comments (more readable):

/* This pattern expects an integer and IP address */ INT // an integer ' ' // followed by single space IPADDR:ip // IPv4/IPv6 address, extracted as 'ip' EOL // line is terminated with line feed
Key Points:
• Patterns interpreted left to right
• Whitespace, line breaks, and comments ignored
• All matchers must match, but only some extract data

Export Names & Data Extraction

A matcher extracts data only when assigned an export name:

INT:seq ',' LD:uname ',' IPADDR:user_ip EOL

With Export Name

IPADDR:ip

✅ Matches pattern
✅ Extracts data
✅ Creates field 'ip'

Without Export Name

','

✅ Matches pattern
❌ No data extraction
❌ Not visible in queries
Export name syntax: MATCHER:export_name

Matcher Expression Syntax

Full syntax (from right to left):

[lookaround] MATCHER ['(' configuration ')'] [quantifier] [optional] [':' export_name]
MATCHER - The core pattern (e.g., INT, IPADDR, TIMESTAMP)
configuration - Optional parameters in parentheses: TIMESTAMP('yyyy-MM-dd')
quantifier - How many times to match: * (0+), + (1+), ? (0-1)
optional - Mark as optional with ~ (outputs NULL if missing)
export_name - Field name for queries: :ip, :username
lookaround - Conditional matching (look ahead/behind)

Step-by-Step Pattern Matching

Input Data:

1,alice,192.168.1.12,bob,10.6.24.183,mallory,192.168.1.3

Pattern:

INT:seq ',' LD:uname ',' IPADDR:user_ip EOL
Step 1: Match INT:seq → finds "1", extracts as seq
Step 2: Match ',' → finds comma, moves forward
Step 3: Match LD:uname → finds "alice", extracts as uname
Step 4: Match ',' → finds comma, moves forward
Step 5: Match IPADDR:user_ip → finds "192.168.1.12", extracts as user_ip
Step 6: Pattern complete, reset and continue with remaining data

Pattern Matching Output

Raw Input:

1,alice,192.168.1.12,bob,10.6.24.183,mallory,192.168.1.3

Structured Output:

seq uname user_ip
1 alice 192.168.1.1
2 bob 10.6.24.18
3 mallory 192.168.1.3
✨ Result: Unstructured log data transformed into queryable structured data!
