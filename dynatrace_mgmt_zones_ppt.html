📋 What are Management Zones?

Management Zones enable logical segregation of your monitored environment into distinct groups.

🎯 Core Purpose

  • Define fine-grained access rights
  • Group related entities together
  • Isolate alerting per business unit
  • Maintain end-to-end visibility

🔧 Entity Types

  • Applications
  • Services
  • Process Groups
  • Hosts
  • Custom Metrics

Key Concept:

Rules are executed periodically in the background. Entities matching rules get zones assigned automatically, while non-matching entities have zones removed.

⚙️ Management Zone Rule Types

Rule Type Use Case Example
Dimensional Data Filter by metric dimensions namespace=prod-us, pipeline=etl-daily
Process Group Group by application/service Java processes running DataPipeline
Host Infrastructure-based grouping Hosts tagged with "market:APAC"
Service Microservice segregation Services containing "broker"
Tags Custom metadata filtering environment:production

💡 Best Practice: Use dimensional rules for METRIC types to filter based on custom dimensions like namespace, pipeline name, or market identifier.

🔧 Solution: Namespace Segregation

Challenge: One alert for multiple pipeline failures

Management Zone: "Market-US-Pipelines" Rule Type: Dimensional rule for METRIC Conditions: - dimension.namespace = "us-market" - dimension.pipeline_type = "ETL" Management Zone: "Market-EU-Pipelines" Rule Type: Dimensional rule for METRIC Conditions: - dimension.namespace = "eu-market" - dimension.pipeline_type = "ETL" Management Zone: "Market-APAC-Pipelines" Rule Type: Dimensional rule for METRIC Conditions: - dimension.namespace = "apac-market" - dimension.pipeline_type = "ETL"

✓ Benefits

  • Separate alert per namespace
  • Individual remedy tickets
  • Team-specific notifications
  • Clear failure attribution

📊 Result

🚨 Alerting Configuration

Setting up per-zone conditional alerts

Step 1: Create Alerting Profile per Management Zone

Settings → Alerting → Alerting profiles → Add alerting profile

Alerting Profile: "US-Market-Critical-Failures" Management Zone Filter: "Market-US-Pipelines" Severity Rules: - Error rate > 0% (immediate alert) - Execution failure detected Notification: - Email to: us-ops-team@company.com - ServiceNow integration (create ticket) - Include: namespace, pipeline_id, error_details

✓ Solution for Challenge 2: Conditional Email Alerts

  • No more empty emails: Alerts trigger only when conditions are met
  • Rich context: Emails include actual failure data
  • Smart deduplication: Prevents alert storms
  • Maintenance windows: Suppress alerts during deployments

📐 Setting Up Dimensional Rules

Configuration Path:

Settings → Preferences → Management zones → Add management zone

Example: Pipeline-Specific Zone

Management Zone Name: "ETL-Pipeline-Customer-Data" Rule 1: Dimensional rule for METRIC Type: METRIC Conditions: - dimension.pipeline_name = "customer_etl" - dimension.environment = "production" - dimension.namespace begins with "prod-" Rule 2: Process Group Conditions: - Process group name contains "CustomerETL" - Tag exists: "pipeline:customer-data"

⚠️ Important Notes

  • Rules execute periodically
  • Complex rules may delay execution
  • All related entities must be present

🎯 Best Practices

  • Use specific dimension keys
  • Avoid overly complex rules
  • Test with preview functionality

🎫 Automated Ticket Creation

ServiceNow / Remedy Integration

Setup: Problem Notifications

Settings → Integration → Problem notifications → Add notification

Notification Configuration: Filter by Management Zone: "Market-US-Pipelines" Notification Type: ServiceNow / Custom Webhook Payload Template: { "short_description": "Pipeline Failure: {ProblemTitle}", "description": "Namespace: {dimension.namespace}\n Pipeline: {dimension.pipeline_name}\n Error: {ProblemDetailsText}", "urgency": "2", "impact": "2", "assignment_group": "Pipeline-Ops-Team", "category": "Data Pipeline", "subcategory": "Execution Failure" }
