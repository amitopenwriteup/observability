Dynatrace Deployment Options

SaaS vs Managed: Choosing the Right Architecture

Deployment Options Overview

Dynatrace offers two primary deployment models, each designed for different organizational needs, compliance requirements, and infrastructure preferences.

☁️ Dynatrace SaaS

Cloud-hosted, fully managed platform

  • Hosted by Dynatrace
  • Zero infrastructure management
  • Automatic updates
  • Global availability
  • Multi-tenant architecture

🏢 Dynatrace Managed

Self-hosted, customer-controlled deployment

  • Deploy on your infrastructure
  • Full data control
  • Customizable updates
  • Air-gapped support
  • Single or multi-tenant

Key Decision Factors

  • Data Residency: Where your monitoring data must be stored
  • Compliance: Regulatory requirements (GDPR, HIPAA, PCI-DSS)
  • Network Topology: Internet connectivity and firewall policies
  • Operational Overhead: Resources available for infrastructure management
  • Update Control: Need for controlled update schedules

Dynatrace SaaS: Cloud-Native Observability

Architecture Overview

Dynatrace SaaS is a fully managed, multi-tenant cloud service where Dynatrace handles all infrastructure, updates, scaling, and availability.

🏗️ Components

  • OneAgent: Deployed on your hosts/containers (customer side)
  • ActiveGate: Optional proxy for restricted environments (customer side)
  • Dynatrace Cluster: Backend processing and storage (Dynatrace managed)
  • UI/API: Web interface and REST APIs (Dynatrace managed)

✅ Advantages

  • No infrastructure to manage
  • Instant availability
  • Always latest features
  • Automatic scaling
  • 99.9% SLA guarantee
  • Global CDN for fast access

📍 Regional Availability

Choose your region:

  • North America (US)
  • Europe (EU)
  • Asia Pacific (APAC)
  • Middle East (UAE)
  • Australia (AUS)
  • Government Cloud (US Gov)

🔐 Security & Compliance

  • Certifications: SOC 2 Type II, ISO 27001, PCI-DSS, HIPAA-ready
  • Data Encryption: TLS 1.2+ in transit, AES-256 at rest
  • Regional Isolation: Data stays within chosen region
  • Access Control: SSO, MFA, RBAC, API tokens
Best For: Organizations wanting immediate time-to-value, minimal operational overhead, and automatic updates without maintenance windows.

Dynatrace Managed: Self-Hosted Control

Architecture Overview

Dynatrace Managed is a self-hosted deployment where you install and operate the Dynatrace cluster on your own infrastructure with full control over data and updates.

🏗️ Components (All Customer Managed)

  • OneAgent: Deployed on monitored hosts/containers
  • ActiveGate: Proxy and data processing layer
  • Cluster Nodes: Backend processing (minimum 3 nodes for HA)
  • Cassandra Database: Time-series data storage
  • Elasticsearch: Log and event storage
  • Load Balancer: Traffic distribution across cluster nodes

✅ Advantages

  • Complete data sovereignty
  • Air-gapped deployment support
  • Controlled update schedule
  • Custom retention policies
  • Network isolation
  • On-premises deployment

📊 Infrastructure Requirements

Minimum (Small):

  • 3 nodes
  • 16 vCPU, 64 GB RAM each
  • 500 GB SSD storage
  • ~10,000 hosts capacity

Large Deployment:

  • 6+ nodes
  • 32+ vCPU, 128+ GB RAM
  • 1+ TB SSD per node
  • 50,000+ hosts capacity

⚠️ Operational Responsibilities

  • Infrastructure: Provision and maintain servers, storage, networking
  • Updates: Plan and execute Dynatrace version upgrades
  • Backups: Implement backup and disaster recovery procedures
  • Monitoring: Monitor the Dynatrace cluster itself
  • Scaling: Add nodes as monitoring needs grow
  • Security: Patch OS, manage certificates, harden infrastructure
Best For: Highly regulated industries, air-gapped environments, strict data residency requirements, or organizations with existing infrastructure and operations teams.

Network Architecture & Connectivity

☁️ SaaS Network Flow

Standard Deployment:

  • OneAgent → Internet → Dynatrace Cloud
  • HTTPS on port 443
  • Outbound only (no inbound)
  • ~1 KB/min per host

With ActiveGate:

  • OneAgent → ActiveGate (internal)
  • ActiveGate → Dynatrace Cloud
  • Reduces firewall rules
  • Local data aggregation

🏢 Managed Network Flow

Typical Deployment:

  • OneAgent → Cluster (internal)
  • All traffic internal network
  • No internet requirement
  • Fully isolated operation

Update Channel (Optional):

  • Cluster → Dynatrace update server
  • HTTPS on port 443
  • Can be disconnected
  • Manual updates supported

🔒 Firewall Requirements - SaaS

  • OneAgent Communication: *.dynatrace.com:443 (or regional domain)
  • ActiveGate (optional): Internal network to ActiveGate, ActiveGate to Dynatrace
  • User Access: Web browser to *.dynatrace.com:443
  • API Access: *.dynatrace.com:443 from automation tools

🔒 Firewall Requirements - Managed

  • OneAgent Communication: Internal to cluster (port 8021, 9999)
  • User Access: Internal to load balancer/cluster (HTTPS 443)
  • API Access: Internal to cluster (HTTPS 443)
  • Cluster Nodes: Inter-node communication (ports 8021, 9042, 9300, etc.)
  • Updates (optional): Cluster to download.dynatrace.com:443
Security Note: Both deployments use certificate pinning and mutual authentication to ensure secure communication between components.

Data Privacy & Compliance

What Data is Collected?

  • Performance Metrics: CPU, memory, response times, error rates
  • Topology Data: Service relationships, dependencies, configurations
  • Request Data: URLs, HTTP headers, SQL statements (configurable masking)
  • Logs: Application and system logs (opt-in)
  • User Data: Session behavior, geographic location (anonymized)

✅ SaaS Data Controls

  • Regional data residency (6 regions)
  • Data never crosses regional boundaries
  • Built-in data masking and privacy rules
  • Automatic GDPR compliance features
  • Data retention: 35 days (default)
  • Data deletion on environment closure
  • SOC 2, ISO 27001, HIPAA-ready certified
